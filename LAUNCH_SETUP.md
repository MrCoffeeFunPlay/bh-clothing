# BH Clothing: live catalogue and owner access

## What is live

- **Catalogue (Supabase):** categories, products, descriptions, colours, front/back images, sizes, fabric weights,
  colours per fabric weight, ILS and USD original prices, fixed sale prices, and timed product sales.
  Every visitor, on any device, sees the same catalogue.
- **Owner area:** `#admin` (Account → Owner area). Sign in with an admin account to create, edit, hide or show
  products and to upload product images. Saves go straight to the database; the page says clearly whether a save
  worked or failed.
- **Database down:** the store shows a "store is unavailable" page with a retry button. It never falls back to old
  or built-in data as if it were the live store.

Still demo / not connected: checkout and payments, orders and receipts (the Invoices tab shows samples), stock
quantities, customer accounts and sign-up, coupons, BH Club, store-wide sales and site settings (those are kept in
the browser only and are labelled as such in the owner area).

## Database changes (migrations)

`supabase/migrations/`:

1. `20261027090000_catalog_and_admin.sql`: tables, row level security, the `admin_save_product` function and the
   `product-images` storage bucket.
2. `20261027090100_seed_catalog.sql`: the catalogue that was in `src/catalog.ts`, unchanged (generated by
   `node tools/supabase/generate-catalog-seed.ts`). No stock quantities; products without a price stay unpublished.

Who can do what (enforced by the database, not by hiding buttons):

| | Read active catalogue | Change catalogue / prices / sales | Upload images | Make someone admin |
|---|---|---|---|---|
| Visitor | yes | no | no | no |
| Signed-in non-admin | yes | no | no | no |
| Admin (in `catalog_admins`) | yes, plus hidden products | yes | yes | no |
| Owner in the Supabase dashboard | yes | yes | yes | yes |

`supabase/archive/` holds the first drafts; they were never applied and must not be run.

## Making the owner an admin (no passwords or keys in chat)

1. Supabase dashboard → **Authentication → Users → Add user → Create new user**. Enter your email and choose a
   strong password yourself. Tick **Auto Confirm User**.
2. Supabase dashboard → **SQL Editor** → run, with your email:

   ```sql
   insert into public.catalog_admins (user_id, note)
   select id, 'owner' from auth.users where email = 'YOUR-EMAIL@example.com';
   ```

   It should say `1 row` inserted. To remove an admin later:
   `delete from public.catalog_admins where user_id = (select id from auth.users where email = '...');`
3. Recommended while customer accounts are not live: **Authentication → Sign In / Providers → Email** → turn off
   **Allow new users to sign up**. (Even if someone signs up, they are not an admin and cannot change anything.)
4. Open the site → `#admin` → sign in.

## Browser settings

The site uses the project URL and the **publishable** key (`sb_publishable_…`) in `src/catalogStore.ts`. That key
is designed to be public; the database rules above decide what it can do. Never put the `service_role` / secret key
or the database password in the code, in GitHub, or in any `VITE_` variable. To point the site at another project,
set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` (see `.env.example`).

## Tests

- `npm test`: prices, sales and the catalogue ↔ database conversion.
- `npm run test:ui`: the storefront in preview mode, and in live mode against a simulated Supabase (unavailable
  database, owner sign-in, saving, failed save, hiding a product, another browser).
- `npm run test:db`: runs the migrations in a local Postgres and checks what visitors, customers and admins can do.
- `npm run build`: type check and production build.
